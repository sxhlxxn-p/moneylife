# 모의투자 저장 API v2

검증용 가상 가격만 사용한다. 첫 가격 묶음은 synthetic-monthly-v1, 종목 TEST-KRW, 관측 월 0~4다. 외부 API 키·실제 주문·실제 시세는 사용하지 않는다.

## 엔드포인트

- `GET /market/series`: 사용 가능한 가격 묶음의 식별자·가상 데이터 표시·종목·지원 기간·해시. 가격 값은 포함하지 않는다.
- `POST /paper-plans`: `{requestId, planId, priceSeriesId}`. 본인 재무 계획의 현재 진행 월에서 투자 스냅샷을 만든다. 기존 계획은 변경하지 않는다.
- `GET /paper-plans?limit=20&offset=0`, `GET /paper-plans/{id}`: 본인 투자 스냅샷 목록/상태. 전체 가격 원본은 응답하지 않는다.
- `GET /paper-plans/{id}/market`: 해당 스냅샷의 현재 월까지의 가격만 반환한다. 미래 월을 지정하는 인자를 허용하지 않는다.
- `POST /paper-plans/{id}/orders`: `{requestId, side: buy|sell, quantity}`. 접수 월·종목·주문 ID는 서버가 정한다. 가격·보유 수량·체결 결과를 클라이언트에서 받지 않는다. 새 스냅샷과 현재 월 계산 결과를 저장하며, 주문은 다음 월에만 체결된다.
- `POST /paper-plans/{id}/advance`: `{requestId, months: 1~12(기본 1)}`. 지원 가격 기간 안에서 시간을 진행한 새 스냅샷·실행 결과를 보존한다. 저장된 이벤트만 적용하며 새 생애 선택을 자동 생성하지 않는다.
- `GET /paper-runs/{id}`: 저장된 투자/비투자 경로·체결/거부·미체결·비교 결과. 조회는 재계산하지 않는다.

모든 POST 응답은 `plan, run`이다. 명령마다 새로운 불변 투자 계획을 만들며 이후 명령은 반환된 plan.id를 사용한다. 같은 원본에 서로 다른 requestId를 사용하면 별도 분기가 생긴다. 저장 목록에서 각각 볼 수 있다.

## 원본·기간·중복·가격

가격 묶음은 서버가 관리한다. 투자 시작 시 데이터 해시와 전체 원본을 DB 내부에 고정하고 이후 자식 계획은 그 원본을 사용한다. 전체 가격과 내부 실행 입력은 API 응답 모델에서 제외한다. 과거 Run 조회에 현재 파일이나 외부 시세를 사용하지 않는다. 미래 월을 앞서 계산한 120개월 결과는 제공하지 않는다.

매도 접수 수량은 현재 보유 수량에서 같은 월의 기존 매도 주문을 뺀 값 이하여야 한다. 아직 체결되지 않은 매수 수량을 매도 가능 수량에 더하지 않는다. 매수는 다음 월의 가격·현금으로 체결 가능 여부를 최종 판단하므로 접수 성공이 체결 보장은 아니다.

requestId는 게스트별로 고유하다. 동일 명령·동일 원본·동일 인자를 다시 보내면 원래 결과를 반환한다. 같은 ID에 다른 인자/명령/원본을 쓰면 409다. 계획·실행 결과는 한 트랜잭션으로 저장하며 엔진 실패 시 둘 다 저장하지 않는다. 주문 취소·계정 복구·다중 종목·DB 마이그레이션은 후속 범위다.

v1 /plans와 /simulations는 그대로 유지한다. 게스트 소유권·Origin 검사와 만료 정책을 공유한다. 다른 게스트의 투자 계획·시세·Run은 ID를 알아도 조회하거나 명령을 실행할 수 없다.
