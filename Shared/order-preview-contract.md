# 주문 전 확인

`POST /paper-plans/{id}/order-preview`에 `{side, quantity}`를 보낸다. 본인 투자 계획만 조회하며 계획·주문·Run을 저장하지 않는다. 가격·종목·수수료·적용 월은 클라이언트에서 받지 않는다. 최종 예약은 기존 `/orders`의 별도 요청이다.

참고값은 **현재까지 확인한 마지막 가격이 다음 달에도 유지되고 거래 가능하다**는 가정이다. 실제 다음 달 가격이나 거래 가능 여부를 읽지 않는다. 서버는 엔진에 현재 월까지의 가격만 전달한다. 과거 재생 데이터의 미래 가격을 바꿔도 참고값이 달라지면 안 된다.

엔진은 기존 월별 계산과 거래 정산을 재사용한다. 다음 달에 예정된 소득·생활비·일회성 지출, 현재 미체결 주문과 새 주문, 월말 저축을 같은 순서로 반영한다. 참고 거래대금·수수료·세금·현금 이동과 참고 조건의 다음 달말 현금·저축·미충족액을 반환한다. 생활비 부족은 주문 전 발생하며 이후 매도 대금으로 지우지 않는다.

가격이 없으면 거래대금과 손익을 임의로 만들지 않고 가격 참고값과 체결 추정값을 null/unavailable로 반환한다. 이전 가격으로 평가 중이면 그 기준 월과 지연 상태를 표시한다. 다음 달 생활비 자체는 저장된 조건에서 확인할 수 있다. 현금 부족 참고 결과는 실제 체결 거부 확정이 아니며 다음 달 실제 가격과 현금으로 다시 판단한다.

보유 수량에서 같은 월 매도 예약 수량을 제외한 수량보다 많으면 409다. 마지막 월·주문 수 한도·정수 수량 검증은 예약과 동일하다. 참고 거래대금이 안전 정수 범위를 넘으면 422다.

화면은 예약 버튼 → 확인 화면 → 예약 확정 순서다. 취소·닫기·Escape·새로고침은 주문을 만들지 않는다. 입력 수량과 투자 계획 ID를 확인 화면에 고정하고 확정 직전에 같은 계획인지 확인한다. 확정 때만 requestId를 만들며 응답 유실은 기존 동일 요청 재확인을 사용한다. 확인 화면 자체에는 미래 가격, 미실행 실제 결과, 외부 API·LLM 호출을 포함하지 않는다.
