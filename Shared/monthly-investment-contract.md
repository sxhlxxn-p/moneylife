# 월별 금융·단일 종목 투자 계산 계약 v2

범위: 가상 가격을 사용하는 순수 엔진 통합. API·DB·주문 화면은 후속 단계다. 기존 현금·저축 Run v1의 형식과 엔진 버전은 유지한다.

## 입력·출력

`simulateWithTrading(state, investment, months=120)`은 정수 원 상태와 `{symbol, priceSeriesId, prices, orders, costs}`를 받는다. months는 초기 상태 조회 0부터 120까지다. `compareWithTrading`은 동일 조건의 투자 없는 경로와 투자 경로를 함께 계산한다.

- prices: `{month: 0~120, price: 양의 정수 원 또는 null, tradable: boolean}`. 월이 중복되거나 가격 형식이 잘못되면 입력 오류다. null/누락은 해당 월 체결 가격이 없다는 뜻이다.
- orders: `{id, symbol, side, quantity, submittedMonth: 0~119}`. 정수 주만 지원한다. 확정된 주문 기록을 재생하며 submittedMonth+1에 체결한다. 동일 ID·동일 내용·동일 접수 월은 중복 제거, 다른 내용이면 충돌 오류다.
- costs는 기존 모의투자 수수료·세금 가정이다. 기본 0은 테스트 가정이며 실제 제도 요율이 아니다.
- 결과: `engineVersion=monthly-investment-krw-v2`, `priceSeriesId`, `monthlyResults`, `summary`, `executions`, `pendingOrders`. 미래의 미접수 주문과 미래 가격 목록은 반환하지 않는다.

## 월 처리

1. 기존 저축 잔액의 이자 반영(Decimal 월별 HALF_UP).
2. 소득 입금, 생활비·이벤트 지출, 부족액 기록.
3. 공유 현금 잔액으로 매도 주문, 매수 주문 순서 처리. 같은 방향은 입력 순서다.
4. 남은 현금에서 가능한 만큼 저축 이체.
5. 현금 + 저축 + 주식 평가액 - 누적 미충족액으로 월말 총자산·목표 계산.

거래용 자금을 추가로 만들지 않는다. 생활비 단계에서 발생한 미충족액은 같은 달 매도 대금으로 자동 상환하지 않는다. 기존 현금 부족 모델의 의미를 유지한다. 이후 현금이 충분해져도 누적 미충족액을 자동으로 없애지 않는다.

체결 가격이 없거나 거래 불가이면 해당 주문을 거부하고 다음 월로 자동 재주문하지 않는다. 평가에는 현재까지의 마지막 유효 가격만 사용한다. `priceMonth`, `stale`로 기준 월과 지연 여부를 표시한다. 과거 가격도 없는데 주식을 보유한 상태는 평가 불가로 중단한다. 0주는 가격 없이 평가액 0이다.

초기 상태는 주식 0주다. 초기 0개월은 어떤 주문도 체결하지 않는다. 경로를 months까지 실행하면 그 이전에 접수한 주문만 체결하고, 해당 월 접수된 주문만 pendingOrders로 남긴다. 다음 월 접수 주문·가격 변경은 이미 계산한 이전 월을 바꾸지 않는다. 접수 시점의 사용자 권한·실제 날짜·미래 시세 비노출은 서버 연결 시 추가 검증한다.

## 비교와 원가

목표는 총자산의 최초 도달 월(초기 달성 0, 기간 내 미달성 null)이다. 비교는 같은 기간 말 총자산 차이와 부족 기간 차이를 반환한다. 목표 월 차이는 양쪽이 모두 달성한 경우에만 계산하고, 한쪽이라도 미달성이면 null이다.

현금 장부는 비거래 현금흐름을 별도로 추적한다. `cash + costBasis = initialCash + netCashFlow + realizedPnl`. 월별 소득·생활비·저축 이동으로 이 값이 변할 수 있지만, 외부 현금 이동을 매매 손익으로 처리하지 않는다. 최종 장부의 cash는 월말 공유 현금과 같다.
