# 게임 중심 화면 실험

개인 브랜치 `suhyeon`에서 검토하는 화면이다. main 반영은 별도로 결정한다.

## 플레이 흐름

1. 출발 화면에서 체험용 조건 두 개 또는 직접 입력을 선택한다. 이미 진행한 여정은 이어갈 수 있다.
2. 체험 조건도 확인 화면에서 확정해야 시작한다. 기기 내 본편만 초기화하며 서버에 저장한 계획과 모의투자 기록은 유지한다. 미확인 이벤트 요청이 있으면 새 출발을 막는다.
3. 목표와 목표까지 남은 기간을 먼저 보고, 한 달 보내기 또는 자동 진행을 선택한다. 결산에는 공용 엔진에서 계산한 소득·생활비와 이벤트 비용·순자산 변화를 표시한다.
4. 집은 독립, 직장은 휴식·이직·교육 선택을 안내한다. 다음 선택으로 이동하면 처리하지 않은 앞선 이벤트부터 진행한다. 은행은 기존 모의투자 화면을 연다.
5. 이벤트 미리보기에서 선택 전후 목표 도달 월을 확인한다. 저장 성공 후 목표 시점과 다음 달 순자산 차이를 표시한다. 비용·소득 변경은 다음 달부터 반영한다.
6. 결과 비교·기존 계획 저장·뉴스 게임은 유지한다. 새 금융 엔진을 만들거나 외부 API를 추가 호출하지 않는다.

## 구현 경계

- `gameplay.js`: 출발 확인, 월별 내러티브, 장소 안내, 선택 결과 표시.
- `styles/gameplay.css`: 게임 화면 전용 스타일. 기존 화면 스타일과 분리한다.
- `dashboard-screen.js`: 렌더링 중 계산한 경로를 목표·리포트·게임 표시에서 재사용한다.
- `server-events.js`: 기존 저장 요청·재시도·중복 방지 흐름을 유지하고 성공한 동일 여정에만 결과 안내를 추가한다.
- 리포트 금액은 원 단위로 변환한 후 반올림해 1만 원 미만 차이도 표시한다.

## 검증

`npm test`에 출발 확인과 취소, 미확인 요청 보호, 월 결산, 생활비 부족·기간 종료, 장소 이동, 이벤트 결과, 원 단위 비교 테스트 8건을 추가했다.

브라우저 통합 테스트는 `npm run test:ui`로 실행한다. 이번 작업 환경에서는 Chromium 실행 시 소켓 생성 권한 오류가 발생해 브라우저 테스트와 화면 캡처를 완료하지 못했다. 실제 화면에서 아래 항목을 확인한 뒤 main 반영을 결정한다.

- 데스크톱과 모바일에서 건물·안내 문구·목표 숫자가 겹치지 않는지.
- 이전 여정 이어하기와 새 여정 확인 취소가 기존 기록을 보존하는지.
- 이벤트 승인 후 결과 안내, 다음 달 비용 반영, 새로고침 복원이 이어지는지.
- 은행의 모의투자, 하단 보관함의 저장·복구·뉴스 게임이 정상 동작하는지.

## 실행

기존 서버 실행 방법은 유지한다. 브랜치를 변경한 뒤 프론트 개발 서버는 중지 후 `npm run dev`로 다시 실행한다. 새로 등록한 정적 파일 경로를 개발 서버 시작 시 읽기 때문이다. 월별 본편 계산은 외부 API 키 없이 사용할 수 있지만 이벤트를 서버에 확정 저장하거나 모의투자를 진행하려면 FastAPI 서버가 필요하다.

## 장면 중심 개편

기존 대시보드형 배치 대신 전용 플레이 화면을 사용한다. 플레이 중에는 좌측 업무형 메뉴를 숨기고 상단에서 내 인생·결과 비교·시작 조건으로 이동한다. 주요 자산 카드·차트·기록·자연어 입력은 기본적으로 접혀 있다.

마을은 `Client/public/life-town.svg` 한 장의 벡터 장면과 위치별 버튼으로 구성한다. 캐릭터·건물·길을 실제 플레이 영역에 배치하고, 하단 이야기의 주 행동을 ‘한 달 살아보기’로 통일한다. 은행의 모의투자는 기존 기능을 그대로 연다. 자동 진행·배속은 시간 설정을 펼쳐 사용한다.

이벤트는 별도의 선택 장면으로 표시한다. 결정 전 목표 시점을 비교하고, 저장 성공 후에는 결과 장면에서 목표 도달 월과 다음 달 순자산 차이를 보여준다. ‘선택한 삶으로 한 달 살아보기’를 누르면 기존 월 진행 함수로 돌아간다. 120개월이 끝나면 주 버튼은 결과 비교로 이동한다.

첫 화면에서 상세 접힘·장면 표시·월 진행·AI 입력 열기·결과 비교·이벤트 진입을 확인하는 1440px/390px 브라우저 테스트를 추가했다. 기존 통합 테스트는 저장·상세 도구를 명시적으로 펼치도록 수정했다. 이번 환경에서는 브라우저의 로컬 서버 접속이 거부되어 화면 캡처와 브라우저 테스트 실행은 검증 대기 상태다.

## 은행: 모의 주식 계좌

KRX 모의증권투자게임의 진행 상태·종목·차트·주문·잔고 정보 배치를 참고해 투자 화면을 재구성했다. 디자인 자산과 코드는 복제하지 않는다. 현재 구현은 한 계좌에 한 종목이며, 다른 종목은 새 사본을 만드는 조건 선택에서 고른다.

- `paper-market-chart.js`: 공용 엔진 결과에서 현재 월까지의 관측 가격만 표시한다. 가격 누락 월은 이전 평가액을 새 종가로 반복하지 않고 선을 끊는다. 6개월·1년·전체 범위, 포인터와 키보드 탐색, 원화 가격 축, 평균 매입가, 체결된 매수·매도 표시를 제공한다.
- 현재 데이터는 월별 종가이며 OHLC·거래량·실시간 호가를 제공하지 않는다. 따라서 캔들·거래량·호가창을 임의 생성하지 않는다. 가상 가격과 실제 과거 주가를 구분한다. 시뮬레이션의 미래 월은 표시하지 않는다.
- 주문 패널은 기존 확인·예약·중복 방지 로직을 사용한다. 다음 달 체결 방식과 서버 API 계약은 유지한다. 하단 계좌 현황에서 보유 수량·평균 매입가·평가액·손익을 표시한다. 기존 순자산 비교 차트는 접어서 열 수 있다.
- 뉴스는 기존의 가상 경제 시나리오로 연결한다. 실제 뉴스나 실제 주문으로 표시하지 않는다. 실제 LLM·외부 시세 API 연결을 추가하지 않았다.
- 검증: 종가 범위·미래 제외·누락 구간·원화 축·시점 탐색·체결 표시·단일 데이터 처리·현재가 미래 제외 테스트 7건을 추가했다. 데스크톱·모바일 거래 화면 통합 테스트도 추가했으며 브라우저 실행은 기존 환경 제한으로 검증 대기다.
