# 게임 중심 화면 실험

개인 브랜치 `suhyeon`에서 검토하는 화면이다. main 반영은 별도로 결정한다.

## 플레이 흐름

1. 출발 화면에서 체험용 조건 두 개 또는 직접 입력을 선택한다. 이미 진행한 여정은 이어갈 수 있다.
2. 체험 조건도 확인 화면에서 확정해야 시작한다. 기기 내 본편만 초기화하며 서버에 저장한 계획과 모의투자 기록은 유지한다. 미확인 이벤트 요청이 있으면 새 출발을 막는다.
3. 목표와 목표까지 남은 기간을 먼저 보고, 한 달 보내기 또는 자동 진행을 선택한다. 결산에는 공용 엔진에서 계산한 소득·생활비와 이벤트 비용·순자산 변화를 표시한다.
4. 집은 독립, 직장은 휴식·이직·교육 선택을 안내한다. 다음 선택으로 이동하면 처리하지 않은 앞선 이벤트부터 진행한다. 은행은 기존 모의투자 화면을 연다.
5. 이벤트 미리보기에서 선택 전후 목표 도달 월을 확인한다. 저장 성공 후 목표 시점과 다음 달 순자산 차이를 표시한다. 비용·소득 변경은 다음 달부터 반영한다.
6. 결과 비교·기존 계획 저장·뉴스 게임은 유지한다. 새 금융 엔진을 만들거나 외부 API를 추가 호출하지 않는다.

## 구현 경계

- `gameplay.js`: 출발 확인, 월별 내러티브, 장소 안내, 선택 결과 표시.
- `styles/gameplay.css`: 게임 화면 전용 스타일. 기존 화면 스타일과 분리한다.
- `dashboard-screen.js`: 렌더링 중 계산한 경로를 목표·리포트·게임 표시에서 재사용한다.
- `server-events.js`: 기존 저장 요청·재시도·중복 방지 흐름을 유지하고 성공한 동일 여정에만 결과 안내를 추가한다.
- 리포트 금액은 원 단위로 변환한 후 반올림해 1만 원 미만 차이도 표시한다.

## 검증

`npm test`에 출발 확인과 취소, 미확인 요청 보호, 월 결산, 생활비 부족·기간 종료, 장소 이동, 이벤트 결과, 원 단위 비교 테스트 8건을 추가했다.

브라우저 통합 테스트는 `npm run test:ui`로 실행한다. 이번 작업 환경에서는 Chromium 실행 시 소켓 생성 권한 오류가 발생해 브라우저 테스트와 화면 캡처를 완료하지 못했다. 실제 화면에서 아래 항목을 확인한 뒤 main 반영을 결정한다.

- 데스크톱과 모바일에서 건물·안내 문구·목표 숫자가 겹치지 않는지.
- 이전 여정 이어하기와 새 여정 확인 취소가 기존 기록을 보존하는지.
- 이벤트 승인 후 결과 안내, 다음 달 비용 반영, 새로고침 복원이 이어지는지.
- 은행의 모의투자, 하단 보관함의 저장·복구·뉴스 게임이 정상 동작하는지.

## 실행

기존 서버 실행 방법은 유지한다. 브랜치를 변경한 뒤 프론트 개발 서버는 중지 후 `npm run dev`로 다시 실행한다. 새로 등록한 정적 파일 경로를 개발 서버 시작 시 읽기 때문이다. 월별 본편 계산은 외부 API 키 없이 사용할 수 있지만 이벤트를 서버에 확정 저장하거나 모의투자를 진행하려면 FastAPI 서버가 필요하다.
