# Decisions

## 현재 결정

- 기존 HTML·CSS·JavaScript 초안은 유지하고 React·TypeScript 이전은 별도 작업으로 진행한다.
- npm workspaces는 `Client`, `Server`, `Engine`, `Shared`, `Test`로 구성하고 lockfile은 루트에서 하나만 관리한다.
- 실시간 멀티플레이가 없는 MVP에는 socket.io를 사용하지 않는다.
- LLM은 별도 Python 서비스가 아니라 초기에는 `Server` 내부 어댑터로 구성한다.
- 금융 수치와 목표 시점은 LLM이 아닌 `Engine`에서 산출한다.
- ORM, 인증 방식, 배포 공급자와 토스증권 인증 방식은 아직 확정하지 않는다.

결정이 바뀌면 날짜, 근거, 영향받는 계약·테스트와 승인자를 함께 기록한다.

## 첫 저장 통합에서 반영한 결정

- 서버는 taewoo 브랜치의 FastAPI·SQLAlchemy·PostgreSQL 구성을 재사용했다. 로컬 검증용 SQLite 실행 경로를 추가했다.
- 클라이언트의 기존 정적 구현은 보존했다. React 전환과 엔진 TypeScript 전환은 수행하지 않았다.
- 목표는 총자산 기준으로 통일했고, 비상금 경고와 분리했다.
- 계획은 명시적 저장 시 불변 스냅샷으로 생성한다. 현재 계산 결과는 브라우저에서 재계산한다.
- 게스트 세션은 DB에 토큰 해시와 만료 시각을 저장한다. 현재 단계에는 계정 복구가 없다.
- 상위의 스택 미정 항목은 당시 기록이다. 최신 구현은 이 결정과 `first-integration.md`를 따른다.

## 서버 계산 통합 (2026-11-08)

- 기존 JS 월별 처리 로직을 공통으로 사용하고, 서버에서는 Node 고정 프로세스를 호출한다. TypeScript 이전과 내부 HTTP 서비스 분리는 이번 변경에서 수행하지 않는다.
- 서버 금액은 정수 원, 이자는 decimal.js로 매월 HALF_UP 반올림한다. 브라우저 실수 계산은 미리보기로 유지한다.
- 성공한 결과만 불변 Run으로 저장한다. planVersion=1, engineVersion=cash-savings-krw-v1과 입력 사본을 보존한다.
- 같은 게스트의 requestId는 중복 실행 결과 저장을 막는다. 5초 시간 제한과 최대 4개 동시 프로세스를 적용한다.
- 사용자의 직접 종목 선택·모의 매수/매도 요구는 후속 명세 paper-trading-plan.md에 반영했다. 실제 주문이나 미래 가격 예측은 범위에 넣지 않는다.
- SQLite·Node·브라우저로 검증하며 PostgreSQL/Docker 실환경 검증은 남아 있다. main 반영은 PR 리뷰 후 진행한다.

## 사용자 승인형 LLM 변경안 (2026-11-08)

- 사용자 요청에 따라 PR #4·#5·#6을 merge commit 방식으로 main에 순서대로 통합했다.
- LLM은 구조화 조건 추출만 맡고, 정수 원 계산과 계획 비교는 서버가 공통 Engine으로 실행한다.
- 변경안은 소유자와 만료를 검사하며 승인 후 Plan·Run·적용 상태를 한 트랜잭션으로 보존한다.
- 기존 월별 이벤트를 보존해 add/subtract를 적용하고 set은 요청 기간의 해당 항목을 고정한다.
- 모델과 키는 서버 설정으로 주입한다. 현재 환경에는 설정이 없어 실제 해석 정확도·지연·비용을 주장하지 않는다.
- 자유 생성 설명 대신 계산 수치가 포함된 정형 설명을 먼저 연결했다. LLM 설명과 평가 데이터셋·실험은 후속 범위다.
