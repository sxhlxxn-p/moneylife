# API 연결 전 LLM 개발과 평가 준비

## 이번 범위

외부 API를 호출하지 않고 운영 코드의 연결과 실패 처리를 검증한다. 모의 응답의 정답 여부를 모델 성능으로 기록하지 않는다. 새 가짜 모델을 운영 서버에 넣거나 규칙 기준선을 AI 대체 기능으로 사용하지 않는다.

## 실행

가상환경을 활성화하고 루트에서 실행한다.

```bash
npm run check:ai:offline
npm run prepare:ai
npm run evaluate:ai -- --mode rules --split dev --output .data/ai-evaluation/rules-dev-current.json
```

오프라인 흐름 검사는 외부 HTTP 전송을 MockTransport로 대체한다. 사용자 조건 저장 → 자연어 변경 요청 → 구조화 응답 파싱 → 서버 검증 → 사용자 승인 → 원본과 새 계획 저장 → 계산·비교 → 결과 해설의 실제 경로를 실행한다. 임시 SQLite DB는 종료 시 제거한다. 환경에 실제 키가 있어도 검증 중에는 오프라인 전용 값과 전송 계층을 사용하고 종료 시 복원한다.

확인하는 항목은 승인 전 원본 보존, 승인 누락 거부, 실제 계산·비교 값, 중복 승인, 재질문의 원래 요청 연결, 기준 월 전달, 음수 조건 거부, 미지원 요청, JSON 오류, 시간 초과, 잘못된 해설의 두 번 검사와 정형 대체, 검증된 사실 문장의 선택·캐시다. 상대 날짜의 추출 결과 자체는 모의 응답이므로 모델의 날짜 이해 능력을 입증하지 않는다.

## 100건 데이터 준비

기존 cases-v1.json의 100건을 유지한다. 열 개 범주마다 개발 6건·최종 4건이며, 개발 60건만 세 번 반복해 기준선을 구한다. prepare는 ID/문장 중복, 분리 수량, 범주 균형, 정답의 스키마와 서버 검증 라벨이 맞는지 점검한다. 데이터의 독립적인 의미 정답 검수는 아직 완료하지 않았다.

개발 검수표는 `.data/ai-evaluation/preparation/dev-review.csv`다. reviewer, decision, notes를 작성한다. 금액 단위, 증감/설정, 기준 월과 적용 기간, 복합 변경 순서, 모호·미지원·유효하지 않은 조건의 분류를 검토한다. 현재 decision은 모두 pending이다. 최종 40건은 개발 검수표에 포함하지 않으며 모델 평가도 실행하지 않았다.

## 실험 준비 상태

규칙 기준선·일반 지시·구조화 출력의 세 경로와 동일한 서버 검증을 준비했다. 실제 모델 모드는 --allow-live가 있어야 실행되므로 키가 설정돼 있어도 기본 실행으로 외부 요청을 보내지 않는다. 지금 단계에서는 이 옵션을 사용하지 않는다.

최종 평가에는 데이터/코드/모델/프롬프트 설정이 같은 전체 개발 보고서가 필요하다. 개발 60건×3회의 caseId와 repetition 조합을 검증하고, 누락·중복·최종 사례 혼입·반복 횟수 차이를 거부한다. 일부 사례 연결 확인 보고서나 요약 보고서는 최종 설정으로 사용할 수 없다.

추출 전 조건 완전 일치, 검증 후 상태·조건 일치, 검증을 통과한 잘못된 변경, 재질문 재현율, 지연·토큰·비용을 구분한다. 모델 없이 실행한 규칙 평가에는 모델 토큰/비용/모델 정확도가 없다. 세 번 반복한 결과는 동일한 60건을 재사용하므로 독립 문장 180건이 아니다.

현재 해설 방식은 서버가 사실 문장을 작성하고 LLM이 순서를 선택하는 구조다. 오프라인 검사는 사실 ID의 중복·누락과 허위 수치 문장의 거부를 검증한다. 자유 문장 생성과의 실제 모델 비교 실험은 아직 실행하지 않았다.

## 결과 확인

`Test/ai/reports/offline-readiness.json`은 이번 검증의 공유용 요약이다. 전체 개발 시도 기록과 검수표는 위 명령으로 재생성한다. 요약 파일은 최종 평가 동결 설정으로 사용할 수 없다. 규칙 기준선 결과를 실제 LLM 성능이나 실제 사용자 분포의 성능으로 소개하지 않는다.
