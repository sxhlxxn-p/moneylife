# 금융 계산 명세 초안

`Engine`은 UI, 네트워크, DB와 분리된 순수 계산 영역이다.

## 월 처리 순서

1. 월초 저축 잔액의 이자 반영
2. 순소득 입금
3. 생활비 지출
4. 이벤트 지출
5. 가능한 현금 범위에서 매도·매수(v2 투자) 후 저축 이체
6. 월말 자산·목표·부족 기록

저축 이체는 자산 간 이동이므로 소비로 중복 차감하지 않는다. 현금 부족 시 자동 차입이나 자동 매각을 가정하지 않는다. 부채 이자·상환과 물가 반영은 아래 [물가·부채 범위](#물가부채-범위)에 따라 아직 처리 순서에 없다.

## 현재 구현 범위

현재 `Engine/src/index.js`는 현금·저축, 소득·생활비, 일회성 이벤트, 기간 소득 변화, 월말 저축 이체와 연 유효 수익률의 월복리를 만 원 단위로 계산한다. 서버용 snapshot.cjs는 동일 처리 규칙에 정수 원과 Decimal 이자 반올림 정책을 적용한다. 투자 확장 v2는 아래 항목과 별도 계약을 따른다. 부채·물가는 아직 구현하지 않았다.

회귀 기준 데이터는 `fixtures/expected-results`에 두며 동일 입력 재현성, 120개월 결과, 0% 수익률, 이체 시 총자산 보존, 현금 부족과 이벤트 1회 반영을 검증한다.

## 목표 기준 수정

목표는 `cash + saved - unpaid`가 목표 금액에 처음 도달하는 월이다. 비상금 300만 원은 목표에서 차감하지 않는다. 현금 부족 경고와 분리한다. `Engine.goalMonth()`와 화면의 목표 진행률에 같은 기준을 사용한다. 금리 0%, 현금 1,000만원, 소득 250만원, 생활비 160만원, 목표 2,000만원의 도달 월은 12개월이다. 첫 달 독립(이사비 300만원, 월 생활비 +30만원)은 22개월이다.

## 서버 결과 v1

서버는 월초 저축 잔액에 유효 연 금리의 월 금리를 적용한다. Decimal 40자리 계산 후 매월 원 단위 HALF_UP 반올림하고 월말 이체는 다음 달부터 이자를 받는다. 입력·엔진 버전·결과를 Run으로 저장하며, 조회할 때 다시 계산하지 않는다. 라이브 미리보기의 실수 계산과 서버의 원 단위 정책을 구분한다.

## 월별 투자 확장 v2

기존 월별 현금 처리에 투자 콜백을 연결했다. 생활비/이벤트를 낸 공유 현금으로 매도 → 매수 후 가능한 저축을 이체한다. 주식 평가액은 총자산에 한 번만 더한다. 저축 인출이나 주식 자동 매도, 부족액 자동 상환을 가정하지 않는다. 주문이 없으면 원 단위 v1과 월별 결과가 같다. 상세 가격·체결·지연·비교 규칙은 `Shared/monthly-investment-contract.md`를 따른다. 투자는 별도 PaperPlan/Run API와 화면에 연결했다. 원화 단일 종목·다음 달 체결·저장된 공통 시점 비교를 지원한다. 실제 외부 시세와 운영 환경 검증은 남아 있다.

## 물가·부채 범위

물가와 부채는 엔진에 구현하지 않았다. 확장 여부는 팀 결정 전까지 미정이다. 비슷해 보이는 기존 기능을 물가·부채 모델로 소개하지 않는다.

| 항목 | 현재 상태 | 비슷하지만 다른 기존 기능 | 확장 시 먼저 정할 것 |
|---|---|---|---|
| 물가 | 미구현. 생활비·소득은 입력값 그대로 유지된다. | 생활비 기간 변경(`changes` expense)은 사용자가 직접 넣는 증액이다. 뉴스 게임 유가 충격(생활비 +10%)은 해당 라운드에만 적용하며 다음 라운드에 누적되지 않는다. | 연 물가율의 월 반영 방식(매월 복리·연 1회), 원 단위 반올림 시점, 소득·목표 금액 연동 여부, 명목·실질 금액 표시 |
| 부채 | 미구현. 대출 원금·금리·상환 입력이 없다. | 미충족액(`unpaid`)은 생활비를 내지 못한 누적 기록이다. 이자가 붙지 않고 자동 상환하지 않으므로 대출이 아니다. | 상환 방식(원리금 균등 등), 부채 이자·상환의 처리 순서, 상환액 부족 시 처리와 `unpaid`의 관계, 목표·순자산에서의 차감 |

확장하면 기존 `cash-savings-krw-v1`과 저장된 Run을 바꾸지 않고 새 엔진 버전을 사용한다. 같은 변경에서 `Shared` 계약·서버 입력 검증·`fixtures` 수기 기대값·이 문서를 함께 수정한다. 물가·부채 입력이 없거나 0이면 기존 버전과 같은 월별 결과여야 한다.

## 독립 기대값 검증

원 단위 계산은 `fixtures/expected-results/krw-cases.json`, 뉴스 게임은 `fixtures/news-game/four-rounds.json`의 수기 기대값과 대조한다. 기대값은 엔진 출력이 아니라 이 문서와 계약의 규칙으로 계산하며 `notes`에 월·라운드별 검산 근거를 남긴다. 규칙을 바꾸면 기대값을 엔진 결과로 덮어쓰지 않고 새 근거로 다시 계산한다.

## 브라우저와 서버의 금액 일치

미리보기와 서버는 동일 snapshot·interest 모듈을 사용한다. 계산은 원 단위이며 Decimal 이자를 월마다 원 단위로 반올림한다. 화면의 만원 표시는 결과를 표시하기 위한 변환이다. 목표·현금 부족 판정에 표시용 반올림을 사용하지 않는다.
