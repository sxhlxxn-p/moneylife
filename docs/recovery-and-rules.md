# 목표·세션·요청 복구와 공용 이벤트

## 목표 복원

현재 목표 이름과 기한은 GameState.goal에 저장한다. 클라이언트의 JourneyStore.snapshot이 모든 저장·AI·이벤트·투자 사본에 같은 목표 정보를 넣는다. 서버 저장을 불러오면 JourneyStore.restore가 목표도 교체하므로 다른 계획의 목표 기한이 섞이지 않는다.

과거 서버 자료에는 이름·기한이 없으므로 고정 기본값을 사용한다. 과거 로컬 자료는 별도 목표 키를 읽는 호환 처리를 유지하며, 새 저장은 하나의 여정 안에 목표도 포함한다. 자세한 형식은 Shared/plan-contract.md를 따른다.

## 미확인 요청

request-journal은 저장 성공 후 요청을 활성화하고, 원래 요청 ID와 입력을 그대로 보관한다. 모의투자와 일반 이벤트 모두 이 저장 원칙을 사용한다. 브라우저 저장이 실패하면 복구할 수 없는 새 요청을 보내지 않는다.

일반 이벤트는 응답 유실 뒤 새로고침해도 ‘이전 선택 결과 확인’으로 동일 ID를 보낸다. 현재 조건이 그 사이 바뀌었다면 이전 결과를 서버에서 확인한 뒤 현재 화면은 유지한다. 다른 선택으로 덮어쓰지 않으며 기존 요청을 먼저 확인하거나 명시적으로 별도 보관하도록 한다.

세션이 교체되거나 원본 투자 사본을 읽을 수 없으면 미확인 요청을 key-archive에 보관하고 활성 참조를 초기화한다. 이 기록은 최근 20개까지 보관한다. 보관은 취소나 미처리 확인이 아니며 이전 소유자의 서버 결과를 새 소유자에게 이전하지 않는다. 브라우저 저장이 불가능하면 보관 실패를 알리고 기존 요청을 유지한다.

## 공용 이벤트 정의

Shared/life-events.json은 life-events-v1, KRW 단위다. 비용·소득 변화·소득 공백 기간과 표시 내용을 함께 정의한다. 프론트는 이 파일을 읽어 만 원 단위 미리보기에 사용하고 서버는 같은 파일로 원 단위 변경을 만든다. 규칙 파일 변경 시 서버와 화면을 다시 시작한다.

이벤트 명령에는 규칙 버전이 포함된다. 예전 기록에서 버전이 없으면 v1으로 해석해 기존 중복 요청 기록과 비교한다. 이후 규칙을 변경할 때는 버전을 올리고 이전 미확인 요청의 처리 정책을 함께 마련해야 한다. 이미 저장한 실행 결과는 다시 계산해 덮어쓰지 않는다.

## 뉴스 화면과 자동 검사

뉴스의 라운드 선택·기록 저장/목록·사본 비교/차트를 파일별로 분리했다. 시작 포트폴리오, 네 가지 가상 뉴스, 충격률, 매도 시점, 원본과 분리된 연습이라는 규칙은 유지한다.

GitHub Actions 구성은 main push와 PR에서 구문·포맷·단위·서버·브라우저 검사를 실행한다. Node 22/Python 3.12를 사용하고 외부 모델 키는 비워 둔다. 로컬 검사 통과와 GitHub에서 실제 workflow가 실행된 결과는 구분한다.

운영용 컨테이너 분리와 PostgreSQL 실환경 복구 검증은 별도 배포 작업이다.
