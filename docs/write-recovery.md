# 계산 일치와 저장 복구

## 계산 경로

브라우저 미리보기와 서버 실행은 `Engine/src/snapshot.cjs` 및 `interest.cjs`를 공유한다. 브라우저는 화면의 만원 단위를 원 단위로 변환해 전달하고, 결과를 화면 단위로 다시 변환한다. 이자는 Decimal 계산 후 월별 원 단위로 반올림한다. 목표 달성 월과 현금 부족 판정도 원 단위 결과에서 결정한다.

경계 금액·여러 금리·120개월 이벤트 사례에서 양쪽 월별 자산을 대조하는 회귀 검사가 있다.

## 탭 간 쓰기

저장·투자 명령·이벤트·AI 적용·세션 갱신은 동일 Origin의 Web Locks를 사용한다. 다른 탭에서 쓰기 중이면 기다리는 대신 재시도 안내를 표시한다. Web Locks 미지원 환경에서는 안전한 저장을 중단한다. 개발 시 localhost 또는 HTTPS를 사용한다.

요청 저널은 매번 최신 localStorage를 읽고 기존의 다른 요청을 덮어쓰지 않는다. 완료 시 자신의 requestId에 해당하는 요청만 제거한다. 요청을 별도 보관하는 것은 서버 명령 취소를 의미하지 않는다.

## 일반 계획 저장

`POST /plan-saves`는 `{requestId, plan}`을 받는다. 동일 소유자의 같은 ID와 같은 내용이면 기존 계획을 반환한다. 같은 ID의 내용이 다르면 409를 반환한다. 계획과 요청 기록은 하나의 DB 트랜잭션에 저장한다. 기존 `/plans` API는 호환성을 위해 유지한다.

브라우저는 저장 requestId와 계산 runRequestId를 요청 전에 보관한다. 계획 저장 뒤 계산이 실패해도 같은 두 ID로 재시도한다. 새로고침 후에도 복구할 수 있으며 기존 계산 없는 저장 계획에는 재계산 버튼을 제공한다. 서버에 저장된 조건과 현재 화면이 다르면 현재 편집 중인 값을 보존한다.

## 세션 만료

새 익명 세션 생성 후 서버 계획 참조 초기화, 이벤트·일반 저장 요청 보관, 투자 상태 초기화를 각각 수행한다. 저장소 오류가 나더라도 나머지 초기화는 계속한다. 보관하지 못한 저널은 정지해 새 세션으로 이전 요청을 보내지 않는다. 저장소가 복구되면 별도 보관 버튼으로 해제한다.

세션 변경은 storage 이벤트와 BroadcastChannel로 다른 탭에 전달한다. 변경 전 시작된 API 응답은 세션 epoch 검사로 거부한다. 익명 세션 변경으로 이전 서버 계획의 소유권이 이전되지는 않는다.
