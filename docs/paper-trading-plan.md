# 직접 거래하는 주식 모의투자 · 후속 개발 명세

상태: 요구사항 반영 및 구현 설계. 현재 실행 화면과 서버 엔진에는 아직 주식 거래가 없다.

## 목적과 사용자 흐름

사용자가 생활비·저축을 관리하는 동일 여정에서 종목과 수량을 선택해 모의 매수·매도한다. 투자금은 실제 여정의 현금에서 빠지고 매도 대금은 같은 현금으로 돌아온다. 게임용 별도 무제한 투자금은 주지 않는다. 투자 없는 계획과 투자 계획의 같은 시점 총자산·목표 도달 월·현금 부족을 비교한다.

1. 과거 시작 연월과 준비된 종목을 선택한다. 첫 버전은 원화 국내 주식, 정수 주, 월 단위만 지원한다.
2. 현재 모의 날짜까지의 가격과 보유 현황을 확인한다. 매수/매도 방향과 수량을 입력한다.
3. 예상 금액·거래 비용·거래 후 현금을 확인하고 주문을 확정한다.
4. 다음 월로 진행하면 해당 월의 확인 가능한 종가로 모의 체결하고 거래 원장을 남긴다.
5. 보유 수량·평가액·실현/미실현 손익과 재무 목표 변화를 확인한다. 되돌려 비교하려면 기존 기록을 수정하지 않고 새 계획으로 분기한다.

## 첫 버전의 거래 규칙

- 과거 데이터 재생 방식이다. 실시간 호가 체결, 실제 주문, 신용/공매도/소수점 거래는 제외한다.
- 화면에 보이는 현재 월 종가로 미래 주문을 확정 체결했다고 처리하지 않는다. 주문은 다음 월 마지막 거래일 종가로 모의 체결한다. 월 중 일별 주문은 확장 범위다.
- 거래 순서: 월초 저축 이자 → 소득·생활비·일회성 지출 → 매도 주문 → 매수 주문 → 남은 현금 범위의 저축 이체 → 월말 평가. 매도와 매수 각각 주문 등록 순서로 처리한다.
- 매도 수량은 현재 보유 수량을 넘을 수 없다. 매수는 체결 시 현금과 수수료를 포함해 검사한다. 현금이 모자라면 해당 주문 전체를 거부하고 이유를 기록한다. 자동 차입이나 다른 종목 자동 매도는 하지 않는다.
- 다음 월 생활비까지 자동 예약해 주지는 않는다. 주문 확인 화면에 현금 잔액과 다음 월 예상 지출을 표시한다.
- 같은 주문 ID 재전송은 중복 체결하지 않는다. 체결은 서버에서만 계산하고 가격·수량·현금 이동을 거래 원장에 기록한다.
- 수수료·세금은 가정값과 적용 범위를 명시하고 서버에서 원 단위 반올림한다. 수치는 실제 제도와 공급자 범위를 확인한 뒤 버전별로 고정한다. MVP 가정과 실제 비용을 혼동하지 않게 표시한다.
- 총자산 = 현금 + 저축 + 보유 주식 평가액 - 누적 미충족액. 매수 원금을 소비 지출로 중복 차감하지 않는다.
- 종목 평균 매입단가는 매수 비용을 포함한 이동평균으로 계산한다. 매도 시 해당 수량의 원가를 제거하고, 순매도 대금과 제거 원가의 차이를 실현손익으로 남긴다.

## 실제 가격 데이터 준비

2026-11-08 확인한 토스 공식 API 문서에는 종목 정보와 `GET /api/v1/candles` 일봉 조회가 명시돼 있다. 실제 조회 가능한 과거 기간과 응답은 승인된 요청으로 추가 검증해야 한다. 공식 약관은 시세를 개인투자자 본인의 매매 목적으로 한정하며 제3자 제공·배포·상업적 활용을 제한한다. 따라서 팀 서비스가 서버 키 하나로 시세를 여러 사용자에게 제공할 수 있다고 전제하지 않는다. 사용자별 인증만으로 서비스 이용 조건이 충족된다고 단정하지 않는다.

공유 서비스 적용 허용 여부를 공급자에게 확인하거나, 교육/모의투자와 사용자 표시가 허용된 가격 공급자를 확보한 뒤 실제 데이터 연결을 확정한다. 그전에는 명시적인 테스트 fixture로 거래 기능을 구현한다.

확인 출처:
- API 가이드: https://developers.tossinvest.com/docs
- 시세 API: https://developers.tossinvest.com/docs/market-data
- Open API 약관: https://home.tossinvest.com/ko/terms/v2?id=752
- 서비스 안내: https://corp.tossinvest.com/ko/open-api

지원이 확인되면 서버 MarketDataProvider로 연결한다. 외부 키와 계좌 정보는 브라우저에 전달하지 않는다. 지원이 부족하면 해당 기능을 지원하는 허용된 공급자를 별도 검토한다. 개발 중에는 출처와 기간이 명확한 테스트 fixture를 사용하고, 테스트 가격을 실제 가격이라고 표시하지 않는다.

- PriceSeries: 종목, 통화, 관측 날짜, 종가, 거래 가능 여부, 가격 조정 방식, 출처, 수집 시각, 데이터 버전.
- Run에는 사용한 가격 묶음 ID를 보존해 외부 데이터가 바뀌어도 같은 결과를 재현한다.
- 거래일 누락·상장 전 기간·거래 정지·잘못된 가격을 검사한다. 체결 가격이 없으면 주문을 거부하며 임의 가격으로 채우지 않는다. 평가에 직전 유효 가격을 쓰는 경우 날짜와 지연 상태를 표시한다.
- 액면 분할과 배당을 처리하지 않는 첫 버전은 해당 이벤트가 없는 검증 기간/종목으로 범위를 제한한다. 조정 종가를 그대로 체결 가격으로 사용하지 않는다. 범위를 넓힐 때 실제 종가와 주식 수 조정을 함께 구현한다.
- 미래 가격은 현재 화면·검색 응답·LLM 입력에 노출하지 않는다. 결과 비교는 이미 실행한 기간만 보여준다. 미래 가격을 미리 본 재실행은 학습용 재시도로 구분한다.

## 코드와 데이터 경계

- Client: 종목 검색/선택, 가격 이력, 주문 입력·확인, 체결/거부 내역, 포트폴리오 카드, 기존 계획과 투자 계획 비교.
- Server: 시세 어댑터와 캐시, 종목/가격 조회 API, 주문 검증·멱등성, 가격 버전 고정, Run 저장.
- Engine: 거래 순서·원가·보유 수량·거래 비용·평가손익 계산. UI와 외부 API에 의존하지 않는다.
- Shared: 별도 투자 계약 v2. 기존 현금·저축 v1 계획과 결과는 계속 읽을 수 있도록 유지한다. v1 Run의 의미를 바꾸지 않는다.
- Test: 거래 정산·보유 수량·현금 보존, 같은 가격이면 비용을 제외한 자산 보존, 부족 잔액 주문 거부, 중복 요청 방지, 과거 Run 재현, 미래 정보 차단.

추가 엔티티는 Symbol, PriceSeries, PaperOrder, Execution, Holding이다. 실행 결과에는 원장·월별 포지션·평가액과 priceSeriesId, engineVersion을 보존한다. 엔드포인트는 `/market/symbols`, `/market/prices`, `/paper-orders`와 `/simulations` v2 확장으로 별도 API 계약을 작성한 뒤 확정한다.

## 구현 순서와 완료 기준

1. 가격 제공 범위 확인과 소량 수집 증명. 실제 데이터 확보 가능 여부를 먼저 결정한다.
2. 고정 가격 fixture로 단일 종목 매수·매도·현금 연결을 엔진에 구현한다.
3. 서버 주문 저장·검증·버전 고정과 재현 가능한 Run을 연결한다.
4. 화면의 주문 확인·보유 현황·거부 안내·투자 없는 계획과 비교를 구현한다.
5. 허용된 실제 가격 어댑터와 연결하고 여러 종목으로 확장한다.
6. 그다음 LLM에 포트폴리오 설명과 조건 변경 제안을 연결한다. LLM은 거래 가격이나 손익을 계산하지 않고, 사용자 확인 없이 주문을 확정하지 않는다.

단일 종목으로 매수 후 월 진행·부분 매도·목표 변화 비교·저장/복원을 끝까지 시연하고 거래 원장과 월별 자산 합계가 일치하면 첫 버전 완료다. 과거 수익률은 미래 수익 보장이나 예측값으로 표시하지 않는다.
