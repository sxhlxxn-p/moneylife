# 프론트엔드 구조

## 상태와 화면

`JourneyStore`가 현재 여정을 소유한다. `current`는 읽기 전용이며 객체·배열은 동결하고 Set은 읽을 때 복사한다. 변경은 set/mutate/restore를 사용한다. 서버 계획 복원과 로컬 복원은 같은 상태 서비스에 반영된다. 브라우저의 만 원 단위와 서버의 원 단위 변환은 기존 plan-state 계약을 유지한다. 재무 요약은 financialProfile에서 파생하며 복사 상태를 따로 저장하지 않는다.

app.js는 초기 복원·이벤트 바인딩·첫 렌더만 담당한다. 화면과 계산·입력·이벤트·저장은 Client README에 적힌 파일로 분리한다. 기존 HTML의 inline handler 이름은 유지해 프레임워크 이전 없이 실행할 수 있다. 파일 분리만을 위해 새로운 화면용 엔진이나 상태 라이브러리를 추가하지 않았다.

## HTTP와 저장

api-client는 fetch·시간 초과·상태/오류 코드 전달을 담당한다. api-errors는 코드별 문구를 반환하는 순수 함수다. 세션 만료는 이벤트로 알리고, 모달은 session-recovery에서 처리한다. server-plans는 계획/계산 결과, server-events는 이벤트 분기에 집중한다.

로컬 저장 키와 형식은 유지한다. 로컬 저장 실패는 숨기지 않고 서버 저장을 안내한다. 저장 내용이 잘못된 경우 초기 조건으로 시작하며 기존 서버 소유권 검사는 유지한다.

## 모의투자

paper-client는 전용 context에 화면·주문·생활 조건·비교·해설·차트·명령·세션 기능을 조립한다. 본편 여정과 투자 상태를 합치지 않는다. 모의투자 전용 context는 클로저 내부에서 공유하며, 외부 공개 진입점은 open이다.

paper-requests는 미확인 요청을 보관한다. stage는 로컬 저장에 성공한 뒤 메모리에 반영하므로 저장 불가 상태의 주문을 전송하지 않는다. 전송 실패로 처리 여부를 모르면 요청 ID를 유지한다. 서버 성공 결과의 참조를 저장한 뒤 요청을 지운다. 검증 오류와 불확실한 오류를 구분하는 기존 정책을 유지한다.

## CSS와 공개 파일

styles.css의 순서대로 base → dialogs → investment → layout → forms → dashboard → overrides를 적용한다. 기존 선택자·미디어 쿼리의 상대 순서는 보존한다. 동적 모달에서 쓰는 선택자를 이름만 보고 삭제하지 않았다. 기존 공통 스타일 중 오래된 화면과 공유하는 규칙은 base에 남아 있다.

기존에는 규칙 뒤에 있어 유효하지 않았던 외부 폰트 import를 진입점 맨 앞으로 옮겼다. 외부 폰트가 허용된 환경에서는 선언한 Noto Sans KR이 정상 로드될 수 있다. 외부 폰트를 사용할 수 없으면 기존 sans-serif 대체 글꼴을 쓴다.

Client/assets.json이 개발 서버에서 공개하는 파일 목록이다. 서버는 프로젝트 전체를 정적으로 노출하지 않는다. check-client는 모든 Client JavaScript의 구문과 HTML 스크립트/공개 파일 목록을 검사한다.

## 포맷과 검증

```bash
npm run format:client
npm run format:check
npm run check
npm test
npm run test:ui
```

Prettier는 루트 개발 의존성으로 고정하고 package-lock에 기록한다. app.js와 paper-client.js의 줄 수 감소는 역할 분리에 따른 것이며 전체 코드가 삭제됐다는 의미는 아니다.

이번 정리에서 단위 테스트 65건과 브라우저 35건을 통과했다. 상태 직접 수정 방지·이전 스냅샷 보존·요청 ID 복원·저장 실패·허용하지 않은 명령 거부를 단위 테스트에 추가했다. 기존 브라우저 테스트는 숨은 전역 변수 대신 상태 API로 접근하도록 바꿨으며 테스트 조건과 기대 결과는 유지했다.

정리 전후 대시보드/재무 입력을 1440px·390px 뷰포트에서 비교했다. 애니메이션 정지 및 외부 폰트 차단이라는 동일 조건에서 네 화면 모두 크기와 픽셀이 일치했다. 모든 화면/이벤트의 시각 비교나 외부 폰트 제공 환경의 픽셀 일치를 보장하는 검사는 아니다.

외부 LLM·토스 실연동이나 PostgreSQL 배포 검증을 이번 프론트 구조 정리의 완료 근거로 사용하지 않는다.
