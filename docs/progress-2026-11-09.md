# 계획서 대비 개발 현황 · 2026-11-09

기준: 보관된 `MoneyLife_Project_Plan.docx`(한국시간 2026-10-22 저장본, 8페이지), Notion `프로젝트 개요`와 `LLM 설계와 성능 실험`, 현재 저장소 코드·검증 결과. 문서의 계획은 실행 성과로 간주하지 않는다. 이후 대화에서 결정된 FastAPI 사용과 모의투자 확장을 구분한다.

## 현재 판단

개인 조건 입력부터 수동 시뮬레이션·이벤트·저장·재조회까지 실행할 수 있다. 별도 투자 사본에서 모의 주문·월 진행·취소·생활 조건 변경과 저장 결과 비교도 동작한다. 자연어 변경·설명·평가 도구는 준비됐지만 실제 모델과 실제 증권 API 호출은 검증하지 않았다. 최종 배포·AI 정량 실험까지 끝난 상태는 아니다.

## 계획서 필수 범위와 현재 상태

### 1. 개인 재무 계산 · 구현/회귀 검증

- 현금·저축·소득·생활비·일회성/기간 비용, 월말 저축 이체, 연 유효금리의 월복리.
- 서버의 정수 원·Decimal 이자 반올림, 1~120개월 실행, 목표 최초 도달·미달성·미충족 지출.
- 대표 사례의 목표 12/22개월과 24개월 자산 차이 1,020만원을 회귀 기준으로 검증한다.
- 브라우저의 실수형 미리보기와 서버의 원 단위 저장 결과는 구분한다. 서버는 1~120개월 실행이 가능하지만 메인 게임 타임라인은 120개월 고정이다.
- 근거: `Engine/src`, `Shared/simulation-contract.md`, `Test/engine.test.cjs`, `Test/plan-state.test.cjs`.

### 2. 게임 화면과 생애 이벤트 · 기본 화면 구현, 통합 보완 필요

- 마을 화면, 재무 입력, 월 진행/정지/배속, 이벤트 선택·일회성 지출, 기록·차트·모바일 대응.
- 메인 게임은 정적 JavaScript와 로컬 상태가 중심이다. 서버 저장은 명시적으로 사본을 저장하는 흐름이다.
- 모든 이벤트 선택이 서버의 독립된 Event 엔티티/분기 API로 자동 저장되는 구조는 아니다.
- 근거: `Client/src/app.js`, `Client/src/server-plans.js`, `Client/src/plan-state.js`.

### 3. 계획·실행 저장과 소유권 · 구현/통합 검증

- FastAPI·SQLAlchemy의 불변 Plan/Run, 게스트 세션, 소유권·Origin 검사, 요청 중복 저장 방지.
- 로컬 SQLite에서 검증했다. PostgreSQL용 구성과 Compose는 있으나 Docker/PostgreSQL 실환경 검증은 남아 있다.
- 계정 로그인·세션 복구·운영 배포까지 완료한 것으로 기록하지 않는다.
- 근거: `Server/app/plans.py`, `simulations.py`, `paper.py`, `database.py`, `Server/tests`.

### 4. 계획 비교 · 일부 구현, 범위 구분 필요

- 메인 게임은 처음 계획·나의 선택·소득 공백 가정의 고정 비교를 제공한다.
- 저장 투자 사본은 같은 출발 조건·가격 버전의 2~3개를 골라 공통 진행 월까지만 비교한다. 순자산·현금/저축/주식·목표·현금 부족과 차이를 표시한다.
- 저장된 일반 Plan과 투자 PaperPlan을 섞어 비교하지 않는다.
- 계획서의 사용자 정의 최선·기본·최악 가정 편집/저장 UI는 아직 없다. 현재 소득 공백 가정을 최악 시나리오 전체 구현으로 간주하지 않는다.
- 근거: `Client/src/app.js`의 compare, `Server/app/paper_comparison.py`, `Shared/paper-comparison-contract.md`.

### 5. 자연어 조건 변경 · 연결 코드 구현, 실제 모델 검증 전

- 소득·생활비·저축의 필드/연산/금액/기간 구조화, 범위·음수·기간 검증, 재질문·미지원 처리, 사용자 승인 후 계산/비교와 새 Plan/Run 저장.
- 외부 LLM 어댑터·로컬 설정/진단 도구와 모의 응답 기반 통합 테스트가 있다.
- 실제 모델 해석 정확도·응답 속도·비용은 아직 측정하지 않았다. 사용자 요청에 따라 실제 연결은 보류 중이다.
- 현재 도구 호출은 고정된 서버 흐름이다. LLM의 자율 후보 탐색/임의 도구 선택은 구현하지 않았다.
- 근거: `Server/app/llm.py`, `ai_changes.py`, `ai.py`, `Client/src/ai-client.js`.

### 6. 결과 설명 · 방어 흐름 구현, 실제 모델 의미 검수 전

- 일반 AI 변경 비교는 자리표시자/서버 수치 연결과 재요청·정형 대체를 제공한다. 숫자 형식 검사는 문장 전체 의미의 정확성을 보장하지 않는다.
- 투자 해설은 저장 결과의 서버 문장을 제공한다. 선택형 LLM은 사실 ID의 선택·순서만 정하고 문장·금액을 직접 쓰지 않는다.
- 기본 투자 해설은 모델을 호출하지 않는다. AI 버튼을 명시적으로 누른 경우에만 외부 호출을 시도하고, 키 미설정/실패 시 기본 해설을 제공한다.
- 실제 모델로 자유 설명 대비 수치·방향·근거 오류를 비교하는 실험은 남아 있다.
- 근거: `ai_explanation.py`, `paper_explanation.py`, `paper_explanation_api.py`.

### 7. LLM 평가 · 데이터/실행 도구 준비, 본 실험 미실시

- 자체 작성 100문장 초안, 개발 60/최종 40 분리, 규칙/일반 지시/구조화 출력 비교 실행기, 설정·데이터·코드 해시 기록.
- 저장된 규칙 기준선 개발 성적은 46/60 완전 일치(약 76.7%)다. 실제 LLM 성적이 아니다.
- 모델/프롬프트 선정, 두 사람의 정답 검토 확인, 최종 세트 고정 후 3회 실행과 평균/편차, 지연/토큰/비용 보고는 남아 있다.
- 계획서의 정확도 90%·미확인 적용 0건·설명 수치 100%는 목표값이다. 테스트 통과 건수만으로 달성했다고 쓰지 않는다.
- 근거: `Test/ai/cases-v1.json`, `evaluate.py`, `reports/rules-dev-v1.json`, `docs/llm-evaluation.md`.

## 사전평가 이후 확장한 투자 기능

단일 국내 원화 종목의 정수 주 모의 매수/매도, 다음 달 체결, 원가·비용·평가/실현 손익, 공유 현금·저축 연결, 비투자 경로 비교, 저장/복원, 주문 전 참고값 확인, 대기 주문 취소, 투자 중 소득·생활비·저축 변경을 구현했다.

CSV 정규 등록과 토스 일봉 읽기 전용 어댑터도 있다. 기본은 실제 종목과 무관한 0~4개월 가상 가격이다. 등록된 과거 가격은 출처·기간·해시로 구분하며 시작 때 원본을 고정한다. 현재 월 이후 가격은 화면이나 LLM에 보내지 않는다.

실제 토스 토큰으로 일봉 수집 성공, 보유 자산 조회를 초기 조건 참고 정보로 연결하는 PoC, 프로젝트 표시/재배포 이용 범위는 확인하지 않았다. 다중 종목·실제 증권 주문·실시간 호가·기업 이벤트/세금 전체 모델은 포함하지 않는다. 내부 모의 주문을 실제 증권 주문 연동으로 기록하지 않는다.

## 계획서와 동기화할 기술 선택

- 프론트엔드: 계획서 React·TypeScript·Vite → 현재 HTML·CSS·JavaScript. React/TypeScript 전환은 미실시.
- 백엔드: 계획서 Node.js·Express → 이후 논의와 구현은 FastAPI·SQLAlchemy. 계획서 기술 표를 수정해야 한다.
- 엔진: 계획서 순수 TypeScript → 현재 순수 JavaScript 모듈과 Node 고정 프로세스 실행. 별도 내부 HTTP 서비스로 분리하지 않았다.
- 검증: 계획서 Vitest·Supertest·Cypress → 현재 Node 내장 테스트·pytest·Playwright Chromium.
- DB: PostgreSQL 구성은 있으나 실제 실행 검증은 SQLite. 배포 공급자·운영 검증은 미완료.

기술 스택 차이를 숨기지 않고 최종 제출 문서·PPT·실행 안내에서 같은 표현을 사용한다.

## 일정 기준 판단과 다음 우선순위

11/08 목표인 계산/저장 기본 연결은 구현했다. 11/15 목표 중 120개월 계산과 일부 이벤트 화면도 있지만 이벤트의 서버 자동 분기와 토스 조회 PoC는 완료로 기록하지 않는다. 11/22 목표인 실제 AI 개발 평가/모델 선정과 사용자 정의 시나리오 비교는 남아 있다. 멘토링 실시·제출 여부는 코드로 확인할 수 없으므로 별도 수행 기록으로 관리한다.

1. 사전발표 계획서·현재 코드·기술 표를 동기화하고 필수 시연 경로를 고정한다.
2. API 연결 보류 중에는 100문장 정답 검토·평가 집합 점검과 게임 이벤트→서버 저장 흐름을 정리한다.
3. 연결 재개 후 실제 LLM 진단→개발 세트 평가→모델/설정 고정→최종 실험을 수행한다.
4. 사용자 정의 최선·기본·최악 조건 편집과 비교 범위를 마무리한다.
5. PostgreSQL/Docker·배포·최종 보고서/영상 검증을 진행한다.

물가/실질 구매력·부채·자율 에이전트는 확장 범위다. 지금은 확장 기능을 계속 늘리기보다 필수 AI 실측과 통합·제출 증거를 완성하는 것이 우선이다.

## 추가: 가상 경제 뉴스 체험

메인 진입점과 투자 사본에서 시작하는 4라운드 뉴스 게임을 추가했다. 금리·유가·경기 회복·고용 충격 아래 보유/절반 매도/전량 매도의 가정 결과를 확인하고 진행한다. 실제 뉴스 분석이나 기존 투자 경로 합성은 아니며 원본 저장 결과는 보존한다. 이자·저축 이체·세금 등을 제외한 별도 프론트 충격 실험이다. [규칙](news-game.md) 참조.

뉴스 게임의 중간/완료 라운드를 별도 서버 기록으로 저장·조회·복원하는 흐름도 연결했다. 공용 계산 엔진이 소유한 투자 Run과 선택 목록에서 재계산하며 요청 중복을 방지한다. 게임 규칙은 가정 실험으로 유지하고 실제 기사 수집이나 투자 원본에 충격을 합성하지 않는다.

후속 구현: 저장 뉴스 대응 기록 2~3개를 선택해 같은 출발점/규칙과 공통 라운드에서 비교한다. 뉴스별 대응·누적 주가 손익·소득/생활비 변화·새 현금 부족과 자산 차이를 표시하며, 현재 진행 및 원본 기록은 보존한다. 이는 가상 뉴스 게임의 비교 확장이며 실제 기사 기반 충격 추정이나 자율 AI를 구현한 것은 아니다.
