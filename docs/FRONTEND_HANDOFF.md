# 머니 라이프 프론트엔드 디자인 및 연동 명세

## 목적과 상태
금융 미래 시뮬레이터를 작은 마을에서 진행하는 생활 게임으로 표현한 동작 프로토타입이다. 시각 방향은 보랏빛 포인트, 밝은 뉴트럴 배경, 원근감 있는 벡터 마을과 캐릭터다. 실제 LLM·증권 계좌·서버는 연결되지 않았다. 순수 계산과 화면의 상호작용은 구현되어 있다.

## 소스 구성
- `Client/index.html`: 시맨틱 화면 구조, 마을 SVG, 접근성 속성
- `Client/src/styles.css`: 디자인 토큰, HUD, 게임 월드, 패널·모달·모바일
- `Client/src/app.js`: 시간 진행, 이벤트, 화면 상태, 로컬 저장, 예시 AI 입력
- `Engine/src/index.js`: 독립 실행 가능한 월별 계산 엔진
- `fixtures/expected-results/example-run.json`: 계산 응답 예시
- `prototype`: 구조 변경 전 정적 초안 원본

루트에서 `npm run dev`를 실행하면 웹 소스와 엔진 패키지를 연결한 개발 서버가 열린다. 외부 폰트가 로드되지 않으면 sans-serif 대체 글꼴로 표시된다. 브라우저 시각·실제 조작 QA는 별도로 필요하다.

## 화면과 인터랙션
| 화면 | 주요 요소 | 동작 및 연동 대상 |
|---|---|---|
| 첫 진입 | 예시 시작·조건 설정·이어하기 | 로컬 진행 상태 유무 판정 |
| 새 여정 | 이름·나이·목표·현금·저축·소득·생활비·저축액·수익률 | 입력 검증 후 초기화·계산 |
| 나의 마을 | 현금·순자산·소득·생활비 HUD, 캐릭터·마을 | 계산월 상태를 월별 표시 |
| 시간 제어 | 시작·정지·1/4/12배속·다음 달·다음 이벤트 | 계산값과 독립적인 재생 제어 |
| 생애 선택 | 독립·휴식·이직·여행·교육의 두 선택지 | 다음 달 적용, 비용·기간·즉시 영향 표시 |
| 내 자산 | 현금·저축·미충족 지출·순자산, 저축·수익률 변경 | 기존 경로에서 다음 달부터 변경 |
| 미래 비교 | 처음 계획·나의 선택·소득 공백 가정 | 최종 순자산·목표 월·부족 개월·차트 |
| 나의 기록 | 시간별 선택 목록 | 기록 조회 |
| 조건 대화 | 예시 저축 변경 요청 | 규칙 기반 해석 → 확인 → 적용 |
| 일회성 지출 | 금액·적용월 확인 | 다음 달 1회 지출 |

은행 클릭은 자산, 집은 독립, 회사는 이직 이벤트를 연다. 미래 이벤트 클릭 시 해당 시점으로 이동을 확인받는다. 선택하지 않은 현재 이벤트는 다음 진행 시 다시 제시한다. 과거 완료 이벤트는 중복 적용하지 않는다. 주요 버튼은 키보드로 조작 가능하며 모달은 Escape 닫기·초점 순환을 지원한다.

## 디자인 토큰
- 배경 `#f5f4f9`, 텍스트 `#292841`, 보조 `#8b899b`
- 주 색상 `#7563df`, 연한 강조 `#f0edfd`
- 구분선 `#e9e6f0`, 성공 `#438c72`, 경고 `#c56868`
- 레일 91px, 헤더 86px, 최대 작업 폭 1610px
- 기본 라운드 13~17px, 모달 23px
- 데스크톱: 좌측 탐색 + 중앙 월드·목표·차트 + 우측 이벤트·기록·대화
- 850px 이하: 하단 탐색, 마을 전체 폭, 패널 재배치
- 500px 이하: 차트·목표·우측 패널 한 열

## 기능 단위 분리 제안
React 전환 시 AppShell, AssetHUD, VillageScene, TimeControls, GoalPanel, AssetChart, NextEventPanel, LifeLog, AssistantPanel, ModalHost로 나눈다. 모달은 WelcomeDialog, SetupDialog, LifeEventDialog, AssetsDialog, CompareDialog, JournalDialog, ChangeConfirmationDialog로 나눈다.

상태는 plan, events, simulationRun, selectedMonth, playState, activeDialog, selectedSpeed, aiRequestState로 분리한다. 현재 파일은 프레임워크 없는 디자인 검토용 구현이다.

## 백엔드 연결 지점
| 현재 함수 | 실제 연동 제안 | 주의 |
|---|---|---|
| restart | POST /plans → POST /simulations | 초기 자산·목표와 단위 검증 |
| simulate | GET /simulations/{id} 또는 계산 요청 | 서버 계산 결과로 월별 재생 |
| choose·updateAssets·applyCost | POST /plans/{id}/branches | 원본 보존·적용월·버전 |
| compare | POST /comparisons | 동일 입력 스냅샷 기반 비교 |
| ask | POST /ai/parse-change | 추출→검증→추가 질문 또는 사용자 확인 |
| 결과 해설 | POST /ai/explain | 실제 계산 지표 ID·값과 일치 검증 |
| 자산 연결 | 허용된 증권 조회 어댑터 | 인증·사용 조건·자산 중복·조회시점 확인 |

API 명칭은 Notion 초안과 동일한 제안이며 아직 엔드포인트가 구현되지 않았다. loading, empty, error, needs_clarification, needs_confirmation, succeeded 상태를 통합 담당이 화면과 매핑한다. 서버 완료 전 fixture로 개발한다.

## 계산 및 단위
이 프로토타입의 금액은 만 원 단위다. Notion의 실서비스 계약 초안은 정수 원 단위이므로 실제 연결 시 API 어댑터에서 단위를 일관되게 변환한다. 수익률 UI는 퍼센트 값이며 엔진은 내부에서 100으로 나눈다.

월별 순서: 시작 저축 이자 → 소득·생활비·이벤트 → 가능한 저축 이체 → 월말 결과. 저축 이체는 자산 이동이다. 소비가 현금을 초과하면 현금은 0으로 하고 미충족액을 누적한다. 순자산 표시에서 미충족액을 차감해 부족을 감추지 않는다. 이는 게임의 부족 기록 모델이며 실제 대출 상품을 뜻하지 않는다. 목표는 비상금 300만 원을 제외한 순자산 기준이다.

초기 범위는 현금·저축이며, 투자·대출·물가·세금·수수료의 완전한 모델은 본 디자인에 미연결이다. 실제 개발 시 계산 명세와 수용 기준을 맞춰 확장한다. 금리 입력은 예시 가정이며 시장 예측이 아니다.
