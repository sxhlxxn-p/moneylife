# LLM 조건 변경 · 구현과 평가

## 현재 구현

소득·생활비·월 저축의 자연어 변경을 외부 LLM이 구조화한다. Server는 금액·기간·변경 후 각 월의 조건을 검증한다. 사용자 확인 후 원본과 후보를 공통 Node 엔진으로 실행하고 새 Plan·Run과 비교 수치를 저장한다. 원본은 보존하며 같은 변경안을 다시 확인해도 새 계획을 중복 생성하지 않는다.

- `app/llm.py`: OpenAI Responses strict JSON Schema 어댑터. 공급자 실패·거부·불완전/잘못된 출력을 중단한다.
- `app/ai_changes.py`: 시뮬레이션 월을 기준으로 기간 검증, 기존 각 월의 이벤트를 포함해 변경 적용.
- `app/ai.py`: 변경안 30분 보관, 게스트 소유권 확인, 승인 후 계산·비교·트랜잭션 저장.
- `Client/src/ai-client.js`: 변경안 확인, 추가 질문 표시, 승인 후 새 계획 복원과 결과 안내.
- 계약: [ai-change-contract](../Shared/ai-change-contract.md).

도구 실행은 서버의 고정 흐름(run_simulation:base → run_simulation:candidate → compare_plans)이다. LLM이 임의 도구를 선택하거나 여러 후보를 자율 탐색하는 에이전트는 아니다. 승인 직후에는 정형 설명을 보여주고, 사용자가 AI 설명 보기를 누르면 지표 참조 방식의 LLM 설명을 별도로 생성한다. 숫자 자리는 서버가 채운다. 임의의 숫자를 자유롭게 쓰는 설명은 제공하지 않는다.

## 설정과 실행

`httpx`를 개발 전용에서 서버 런타임 의존성으로 이동했다. `pip install -r Server/requirements-dev.txt`로 갱신하고 루트 `npm ci`로 엔진 의존성을 준비한다.

Compose는 `Server/.env`에서 `LLM_PROVIDER=openai`, `LLM_MODEL`, `OPENAI_API_KEY`를 읽는다. 실제 값을 Git에 올리지 않는다. 모델은 Responses API의 strict JSON Schema 출력을 지원하는 모델 ID로 설정한다. 특정 모델을 임의로 기본 선택하지 않는다.

Docker 없는 `run_local.py`는 .env를 자동으로 읽지 않는다. API를 실행하는 터미널에서 세 변수를 환경변수로 설정한 뒤 실행한다. 키는 채팅·명령 이력·코드에 붙여넣지 말고 사용하는 개발 환경의 비밀정보 설정으로 주입한다. 키나 모델이 없으면 LLM_NOT_CONFIGURED를 반환하고 수동 기능은 그대로 쓸 수 있다.

실행 순서:

1. API 서버와 Client 개발 서버를 실행한다.
2. 미래에게 물어보기에 `다음 달부터 생활비를 20만 원 줄여줘`를 입력한다.
3. 현재 조건이 기준 Plan으로 서버에 저장되고 LLM 해석을 요청한다. 아직 현재 여정에는 적용하지 않는다.
4. 표시된 항목·금액·연월을 검토하고 `확인하고 새 계획 계산`을 누른다.
5. 원본/변경 계획의 목표 시점·120개월 말 자산 차이·부족 기간 차이를 확인한다.
6. 정보가 부족하면 표시된 질문의 답을 원래 요청과 합쳐 완성된 문장으로 다시 요청한다.

LLM에는 요청 원문과 기준/다음/최종 연월만 전송한다. 프로필 이름·저장 기록·세션 토큰·계좌 정보는 보내지 않는다. 사용자가 직접 요청에 적은 개인정보까지 자동으로 제거하지 않으므로 화면에 외부 전송 안내를 표시한다.

공식 구현 참고: https://developers.openai.com/api/docs/guides/structured-outputs (2026-11-08 확인).

## 검증 범위

테스트는 모델 응답과 외부 HTTP를 대역으로 바꾸되 실제 FastAPI·SQLite·Node 계산을 사용한다. 조건 변환·기간 밖 보존·추가 질문·미지원 요청·음수/과거 기간 거부·사용자 격리·명시적 확인·만료·재확인·실패 후 재시도를 확인한다. 브라우저에서도 승인 전 상태 보존과 승인 후 저장·계산·화면 복원을 확인한다.

현재 실행 환경에는 API 키와 모델이 없어 실제 외부 모델 호출과 해석 품질은 검증하지 않았다. HTTP 대역의 성공은 실제 모델 정확도나 응답 속도 성과가 아니다. Docker/PostgreSQL도 별도 실환경 검증이 필요하다.

## 조건 추출 평가 구현

평가 데이터 100건과 rules/plain/structured 실행기를 추가했다. 개발 60건·최종 40건은 범주별로 고정했고 최종 평가에는 전체 개발 보고서의 설정 고정을 요구한다. [실행·지표·결과](../Test/ai/README.md)를 따른다. 규칙 기준선은 개발 세트 46/60건 일치이며 실제 LLM 결과는 아직 없다.

## 후속 평가

- 고정 문장 100건: 개발 60건, 최종 평가 40건. 단일·복합·시점·기간·모호·미지원·실행 불가 요청을 포함한다.
- 규칙 기반 / 일반 지시 / 구조화 출력+서버 검증을 동일 문장으로 비교한다.
- 모델·프롬프트·설정을 개발 세트에서 선택하고 고정 후 3회 평가한다.
- 변경 조건 완전 일치율, 잘못된 적용 비율, 재질문 정확성, 지연과 토큰 비용을 기록한다. 검증 전 추출과 최종 출력을 분리한다.
- 지표 연결 설명과 재요청·정형 대체 흐름은 구현했다. 후속 실험에서 자유 설명과 비교하고 수치 정확도뿐 아니라 방향·원인 서술의 의미 오류도 별도 검수한다.

## 지표를 연결한 LLM 설명

`POST /ai/explain`에 본인 Run의 runId를 전달한다. 비교 수치가 있는 AI 변경 Run만 설명하며, 사용자 제공 지표나 자유 실행 도구는 받지 않는다. 모델에는 엔진의 비교 수치와 표시값만 보낸다. 원본 Run을 수정하지 않고 검증된 설명을 별도 AIExplanation에 보존한다. 저장된 설명은 재조회 시 재생성하지 않는다.

모델은 baseGoal/candidateGoal/assetDifference/shortageDifference 자리표시자를 각 한 번 사용한 문장을 만든다. 서버는 누락·미지원 참조·직접 숫자·지원하는 한글 수치 표현을 거부하고, 승인한 자리표시자에 엔진의 정확한 표시값을 삽입한다. 검증 실패는 한 번 재요청하고 계속 실패하면 정형 설명으로 대체한다. API 장애/거부는 바로 대체하고 계산 결과와 계획은 유지한다. 키가 없으면 호출하지 않고 정형 설명을 유지한다.

검증된 설명에는 source=llm, 대체에는 source=template과 fallbackReason을 반환한다. verifiedNumbers는 정해진 지표 참조·수치 형식 검사와 서버 값 연결을 뜻한다. 원인에 관한 서술이나 모든 자연어 표현의 의미 정확성을 증명하는 지표가 아니다. 실제 모델 설명의 의미 검수와 자유 설명 대비 실험은 남아 있다.

실제 외부 모델 호출은 아직 없다. 테스트 대역으로 직접 숫자 생성 → 재요청 → 지표 연결 성공, 계속 실패 시 대체, 별도 저장·재조회·소유권을 확인했다. Chromium에서도 AI 설명 버튼과 수치 연결, 모바일 가로 넘침 없음을 확인했다.
