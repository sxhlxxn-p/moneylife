# 계획 저장·서버 계산·결과 조회 실행 안내

## 이번에 연결한 범위

기존 정적 화면을 그대로 사용해 현재 여정의 초기 조건·진행 월·비용 변경·이벤트 선택·기록을 서버 DB에 저장하고 다시 불러온다. 저장할 때마다 새 스냅샷을 만들고 불러온 원본은 보존한다. FastAPI가 동일한 JS 계산 엔진을 Node 프로세스로 실행하고, 입력·엔진 버전·월별 결과·요약을 Run으로 저장한다. LLM과 주식 투자는 아직 연결하지 않았다.

## Docker로 실행

```bash
npm ci
npm run dev:server
```

별도 터미널:

```bash
npm run dev:client
```

브라우저에서 `http://localhost:5173`을 연다. Client 개발 서버는 `/api/*`를 FastAPI의 `http://127.0.0.1:3000`으로 전달한다. 다른 API 주소는 `API_BASE_URL` 환경변수로 지정한다. 현재 Node 개발 서버는 `.env`를 자동으로 읽지 않으므로 필요한 값은 셸에서 설정한다.

Compose는 기존 FastAPI + PostgreSQL 구성을 사용한다. DB 테이블은 개발 서버 시작 시 생성하며 기존 테이블을 변경하는 마이그레이션 기능은 아직 없다. Docker 없는 환경에서 아래 SQLite 실행·테스트로 통합을 검증했으며, 실제 Docker/PostgreSQL 환경의 실행 검증은 별도로 필요하다.

## Docker 없는 로컬 실행

Python 3.12와 Node.js 18 이상이 필요하다. 저장소 루트에서:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r Server/requirements-dev.txt
npm ci
npm run dev:server:local
```

별도 터미널에서 `npm run dev:client`를 실행한다. 로컬 실행 명령은 `DATABASE_URL`이 없으면 `.data/dev.db`에 SQLite를 사용한다. `.data`는 Git에 포함하지 않는다. 이미 DATABASE_URL을 설정한 경우 해당 DB를 사용한다. 가상환경 활성화가 안 된 새 터미널에서는 `.venv/bin/python Server/run_local.py`로 실행할 수 있다.

## 확인 순서

1. 시작 조건에서 이름·소득·지출·자산·목표를 입력한다.
2. 시간을 진행하고 이벤트를 선택한다.
3. 상단의 `서버 계산·저장`을 누른 뒤 계획과 계산 결과의 저장 완료 메시지를 확인한다.
4. 페이지를 새로고침하고 `저장한 여정`을 연다.
5. 저장된 항목을 선택해 진행 월·자산·선택 기록을 확인한다.
6. `계산 결과`에서 120개월 요약과 월별 원 단위 결과를 확인한다.
7. 변경 후 다시 저장하면 원본과 새 스냅샷이 각각 목록에 남는다.

서버 저장은 명시적으로 버튼을 누를 때만 수행하며, 기존 기기 내 자동 저장도 유지한다. `시작 설정`에서 새로 시작하면 부모 계획 연결이 초기화된다. 서버 조회나 저장이 실패해도 현재 여정은 바꾸지 않는다. 쓰기 요청이 시간 초과되면 서버에는 저장되었을 수 있으므로 목록에서 확인한 뒤 재시도한다.

목표는 총자산(현금 + 저축 - 누적 미충족액) 기준이다. 종전의 비상금 300만 원 자동 차감은 제거했다. 현금 300만 원 미만 경고는 별도 표시한다. 기존 기기 저장본도 새 목표 기준으로 표시된다.

## 게스트 세션

로그인 대신 30일 HttpOnly 게스트 쿠키를 사용하고 DB에서 소유자를 검사한다. 다른 게스트는 계획 ID를 알아도 읽거나 부모로 지정할 수 없다. 토큰 원문은 DB에 저장하지 않는다. 서버 재시작 후에도 DB와 쿠키가 유지되면 같은 계획을 불러올 수 있다.

쿠키를 삭제하거나 만료시키면 이전 계획 복구 기능은 없다. 이 경우 새 여정을 시작해 저장할 수 있다. 여러 기기 동기화·계정 복구·실계좌 인증을 제공하는 로그인 시스템으로 해석하면 안 된다. HTTPS 배포 시 `COOKIE_SECURE=true`로 설정하고 같은 출처의 `/api` 역방향 프록시를 구성한다.

## 테스트

```bash
npm run check
npm test
cd Server
../.venv/bin/python -m pytest -q
```

API 테스트는 임시 SQLite DB에서 실제 INSERT/SELECT와 Node 엔진 실행을 수행한다. 서버 실행과 테스트 전에 루트에서 `npm ci`로 `decimal.js`를 설치해야 한다. DB 재시작 후 복원, 원본 보존, 사용자 분리, 잘못된 금액과 기간, 외부 Origin 쓰기 거부를 검증한다. PostgreSQL 연결 자체의 성공/실패 테스트는 기존 모의 테스트를 유지한다.

## 서버 계산 규칙과 실패 처리

계산은 저장된 Plan의 입력만 사용한다. 브라우저가 계산 결과를 전송할 수 없다. 이자는 Decimal 40자리 정밀도로 계산해 매월 원 단위 HALF_UP으로 반올림하고, 월말 저축 이체에는 다음 달부터 이자를 적용한다. API는 1~120개월, 현재 화면은 120개월을 실행한다. 같은 requestId 재전송은 기존 Run을 반환하며 조회는 재계산하지 않는다.

계획 저장 후 계산에 실패하면 계획은 유지되고 성공한 계산 결과만 저장한다. Node 미설치·5초 시간 초과·잘못된 엔진 출력은 503이다. 현재 화면의 라이브 차트는 기존 실수 계산 미리보기이므로 서버의 원 단위 반올림 결과와 소액 차이가 날 수 있다. 서버의 저장 결과는 별도 `계산 결과` 화면에서 확인한다. 계약은 [simulation-contract](../Shared/simulation-contract.md)를 따른다.

Docker 이미지는 Python과 Node 실행 파일·Decimal 의존성을 포함하도록 구성했다. 이 환경에는 Docker가 없어 이미지 빌드와 PostgreSQL 동작은 검증하지 못했다.
